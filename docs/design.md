# 当前设计

## 执行链

打开助手查询活动，若唯一匹配同一讲座的另一场次则提议加入；用户选择线上／线下优先并开始等待。一个任务最多包含两个候选，两个挂载按钮打开同一个面板。

预约时间按上海时区解析，所有截止判断和倒计时使用本机 `Date.now()`。固定在开放前 30 秒取图、OCR，在开放时间后 50 ms 提交；OCR 晚于该时刻完成则立即提交。重试与候选切换不叠加额外的 50 ms 等待。不读取服务器时间或计算偏移。

等待期间每分钟用活动详情检查会话，开放前约 40 秒补最后一次检查。检查不取验证码；进入验证码准备后不再启动检查，也不采用旧检查的迟到反馈。准备过程不等待在途详情响应。

OCR 资源在浏览器内校验、缓存并预热，图片只作为局部参数传给 OCR。共用进行中的初始化 Promise；预热失败后实际使用时再试一次，持续初始化失败则停止。没有验证码图片、数字、人工编辑或模式切换 UI。

## 反馈与状态

- 识别失败、非四位数字、明确验证码拒绝或“尚未开放预约”：当前候选立即换图识别，再按时间门槛提交。
- 明确满员：标记当前场次，串行转向下一候选并取新图；无下一候选则结束。
- 成功或“已预约”：查询预约记录；写入超时、断网或格式异常也先核验，不重复提交，不切候选。
- 预约记录最多核验三次；仍无法确认则显示“重新核验”。
- HTTP 登录失效暂停并保留意图，限流停止。验证码取图的网络失败最多尝试三次，间隔 1、2 秒；它与立即执行的 OCR／明确验证码拒绝重试不同。

单目标保留已预约、取消、截止和已知满员拦截；双候选满员切换只以提交的明确业务反馈为依据。任一候选已有预约则不再预约另一份。不监测余位，不自动取消预约。

`generation` 废弃关闭／恢复／切换前的异步结果，`ocrEpoch` 废弃旧轮次验证码结果。关闭取消计时及重试等待；提交／核验期间不能关闭。同源 Web Lock 保证一个执行器持有验证码会话。

## 界面与恢复

单候选作为候选列表只有一项的特例；各场次行展示等待、满员、提交、核验、成功或失败。元数据尚未取得时才显示独立状态行。收起不结束任务；站内列表／详情切换只重挂载按钮，不关闭任务，候选按钮同步显示状态。

待办只保存目标、候选顺序／索引、截止与核验标志，不保存图片或答案。倒计时不重复写相同意图，提交前同步标记待核验。刷新或登录返回先恢复元数据；未确认的提交直接恢复核验，即使预约已截止也不删除待核验屏障。明确终态或关闭清除记录。离开整页保留意图，从浏览器页面缓存恢复时重新打开待办；不会复用旧验证码。

电脑休眠、后台节流、浏览器关闭与认证硬过期不因上述处理而获得执行保证。

## 日志

日志异步写入独立缓存，导出在左侧。仅记录操作结果耗时、关键提交时间、安全业务反馈、处理决定与终态；保留计时延迟警告。不采集服务器时间。格式及保存规则见 [诊断日志](diagnostics.md)。
