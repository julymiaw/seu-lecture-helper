# 本地识别与弹窗

## 使用流程

定时预约提供等宽分段选择“自动识别／手动输入”，在倒计时、取图和识别过程中可切换，提交及核验期间暂时锁定。默认自动；仅定时预约的主动选择会保存到 localStorage。加载失败导致的临时回退不会改掉下次打开时的偏好。

v0.3.5 余位监测独立启用自动识别，默认禁用手动选项；识别失败和验证码错误先立即查询余位，仍有名额就换图重试，不设次数上限和固定等待；模型资源不可用直接回退。退出监测回到定时预约时恢复原偏好。

```text
打开弹窗 → 读取活动与开放时间
          ↘ 自动模式准备／缓存／预热 OCR
到点获取验证码 → 自动：本地推理 → 一次提交 → 查询核验
                手动：聚焦输入框 → 回车／按钮提交 → 查询核验
```

首次打开自动模式会下载资源，约 27 MB；手动模式不发起 OCR 下载。关闭弹窗不会中断已开始的公共资源下载，资源可以供下次打开复用，但迟到的准备或识别结果不能操作已关闭的任务。切换模式、换图、关闭均使旧识别结果失效。

识别结果仅在恰好 4 位 ASCII 字母／数字时自动提交；这是当前自动提交的保守格式条件，不宣称服务端永远只生成这一格式。模型不使用数字过滤。不完整结果、图像解码或推理失败会先自动换图重试，不调用在线服务。每次先查询最新人数，仍有余位就立即换图重试，不设次数上限或额外等待；查询失败、人数未知、满员或预约结束时停止。

明确的验证码业务错误也走上述立即查询人数／换图重试流程。关闭或切换预约方式使迟到的查询、取图和识别结果失效。模型资源无法加载时仍回退手动，不反复下载。网络结果不明时仍按原设计核验，不能因 OCR 重复预约。

## 模型与资源

- 推理引擎：固定 `onnxruntime-web@1.30.0/wasm`，单线程；JavaScript 加载器打包进 `.user.js`，通过 `wasmBinary` 提供已校验二进制，不动态加载远程 JavaScript，不需要 Worker 或本地服务。
- 模型：`ddddocr-node@2.3.0` 的 `common_old.onnx` 和对应字符表。old 在两张保存图上的结果与 beta 相同、体积更小；不据此宣称其总体准确率或速度优于 beta。
- 预处理：Canvas 等比缩放到高 64，灰度、归一化 `[-1,1]`；CTC 贪心解码，合并相邻重复标签、移除空白标签，保留被空白隔开的重复字符。
- 初始化：加载模型后推理一张空白输入，预热 WASM；同一页复用 session。
- 资源清单：`src/ocr-assets.json` 固定版本、字节数与 SHA-256。CacheStorage 保存公开资源，每次读缓存仍校验，损坏则删除重下；存储不可用时使用内存。不会在后台轮询或自动更新模型。
- 网络：jsDelivr 主源、UNPKG 备用，每源每资源最多一次、单请求最多 60 秒；`credentials:'omit'`、`referrerPolicy:'no-referrer'`。资源请求与学校的同源预约请求分开。图片只用于浏览器内存推理，不写缓存、不上传。

## 挂载按钮与视觉

新增按钮继承相邻学校按钮的尺寸类，并读取其实际字体、行高、内边距、边框宽度、圆角和高度。四字原按钮还同步实际宽度，保留助手的绿色配色。重复扫描只在尺寸或样式变化时更新，避免 MutationObserver 自激循环。

弹窗采用浅灰绿色分段底板、白色选中项、细线图标及准备状态；375 px 窄屏验证无横向溢出。采用原生 radio，支持键盘和读屏；验证码输入框在进入手动阶段聚焦，倒计时或准备状态更新不会反复抢走焦点。

## 验证边界

本轮测试在虚构 HTTPS 源运行完整分发文件。OCR 资源由本地固定样例响应，模型和 WASM 确实执行；预约服务是模拟响应。另对公开主源的模型、字符表和 WASM 完成实际下载，文件大小、SHA-256 与 CORS 均通过核验；没有在用户的学校会话中测试下载、CSP 或 Tampermonkey 执行环境。

离线实验的两张真实图片结果见 `experiments/ocr/results.md`；本轮正式集成测试生成已知 `3253` 图片，不把合成图片冒充新增真实样本。实际验证码整图准确率仍需更多独立样本评估。

2026-10-13 新增 10 张真实验证码的小样本离线评估，结果与限制见 [评估记录](ocr-evaluation-2026-10-13.md)。
