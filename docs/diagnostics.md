# 诊断日志

从 0.3.7 起，脚本自动将诊断信息输出到浏览器 Console，不增加弹窗内容，不上传日志，也不另行保存到网站存储。

建议开始等待前打开开发者工具的 Console，开启 **Preserve log／保留日志**，筛选 `[SEU预约助手]`。失败后复制同一 `task` 的日志到 GitHub Issue。页面关闭后不能保证找回日志；保留日志选项也不是跨浏览器重启的持久存储。

每条日志包含版本、任务编号、ISO 时间 `at`（UTC）、任务内累计耗时 `elapsedMs`、事件及相关字段：

日志级别：正常进度用 `log`；满员、结束、取消、业务拒绝、网络故障、登录异常、限流及结果待确认用 `warn`。响应格式变化或未预期的程序异常用 `error`。`phase:failed` 表示任务已停止，并不直接决定日志为 error；业务失败与程序异常分别记录。

| 字段／事件 | 用途 |
| --- | --- |
| 等待期间登录检查 | 每分钟检查是否仍可获取验证码，失败分类 |
| 计时回调延迟 | `delayMs` 与标签页可见性，定位后台节流或休眠后的延迟 |
| 活动查询 | 打开活动的查询耗时 |
| OCR准备与预热 | 是否在开放前准备好识别引擎 |
| 开始取图轮次 | `round`、`afterOpenMs`、`plannedCaptureAt`、`captureDelayMs`、`serverOffsetMs`、`ocrReady`、标签页可见性 |
| 验证码获取、OCR识别、预约提交、预约记录核验 | 开始、完成／失败及 `durationMs` |
| OCR输出检查 | 输出长度与格式是否合格，不包含识别结果 |
| 重试与状态变化 | 重试原因、提交次数、最终状态 |
| `kind`、`reason`、`httpStatus`、`responseCode` | 错误分类、HTTP 状态码及业务返回码；不再重复记录 businessCode |
| `stale` | 返回时任务或 OCR 已切换，结果不再适用 |

`reason` 中 `captcha-rejected` 表示验证码相关业务提示，`full` 表示满员，`timeout` 表示请求超时，`not-open` 表示未开放，`already-booked` 表示需核验已有预约。业务失败额外记录 `serverMessage`、`responseCode`、`responseData`；消息中的凭据、图片和独立四位数字会替换。不记录异常堆栈或任意响应对象。未知提交结果仍先核验。

日志不包含密码、Cookie、验证码图片、验证码答案、完整请求或响应。活动 ID 和人数属于诊断信息。阶段耗时包含该阶段的等待与处理，不能直接区分服务器排队与网络延迟；`afterOpenMs` 基于估算的服务器时间偏差，不能视为精确的服务器到达时间。普通请求与 OCR 的计时可以帮助定位瓶颈，但不能单凭日志证明未抢到的唯一原因。
